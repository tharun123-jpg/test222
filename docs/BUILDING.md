# Building and installing the After Effects plug-ins

This page is about the part that needs Adobe's SDK. If you only want to work on the pixel
algorithms, `make` and `make test` are all you need and you can skip it entirely.

There are three steps, and the third one is the one people lose an afternoon to:

1. build the binaries,
2. attach the PiPL resource to each one,
3. copy them where After Effects looks.

---

## 1. Get the SDK

<https://developer.adobe.com/after-effects/> — download the After Effects SDK for your platform
and unzip it anywhere. You are looking for a directory containing `Examples/Headers`:

```
AfterEffectsSDK/
  Examples/
    Headers/        <- AE_Effect.h, AE_EffectCB.h, ...
    Util/           <- AEGP_SuiteHandler.h, Param_Utils.h, ...
    Headers/SP/     <- SPBasic.h, ...
```

Check the path before you build, because the failure mode is an unexplained include error:

```bash
ls "$AE_SDK_ROOT/Examples/Headers" | head
```

---

## 2. Build

```bash
make plugins AE_SDK_ROOT=/path/to/AfterEffectsSDK
```

Everything lands in `build/plugins/`. Eight effects plus the AEGP:

```
build/plugins/MotionGraphicsToolkit_FeedbackEcho.aex
build/plugins/MotionGraphicsToolkit_ChromaticSplit.aex
... and six more
build/plugins/MotionGraphicsToolkit_AEGP.aex
```

With CMake:

```bash
cmake -B build -DAE_SDK_ROOT=/path/to/AfterEffectsSDK
cmake --build build --config Release
```

### Why eight binaries rather than one

Adobe's own guidance is "one PiPL, and one plug-in, per code fragment". A single binary
containing several PiPLs works in After Effects and nowhere else — not even Premiere Pro — and
it means any change to any effect ships a rebuild of all of them. The interesting algorithms are
not duplicated: each of the eight plug-ins links the same `mgtk_core` static library, and its own
source file is six lines naming an entry in the effect registry.

---

## 3. Attach the PiPL resource

**A plug-in without its PiPL will not load, and After Effects will not tell you why.** It simply
will not appear in the menu. If you have got this far and the effect is missing, this step is the
reason nine times out of ten.

The resource files are generated by `make plugins` (or `make gen-pipl`) into `resources/pipl/`,
one per effect, named after the match name.

### Windows

The SDK ships the tools you need in `Examples/Util/`. From a Developer Command Prompt, with
`AE_SDK_ROOT` set:

```bat
cd resources\pipl

REM Resource file -> .rc, one per effect
"%AE_SDK_ROOT%\Examples\Util\pipltool.exe" -sc motiongraphicstoolkit_anamorphicglow.r my_pipl.rc

REM .rc -> .res
rc /r /fo my_pipl.res my_pipl.rc

REM and into the binary
link /dll /noentry /machine:x64 /out:patched.aex ^
     ..\..\build\plugins\MotionGraphicsToolkit_AnamorphicGlow.aex my_pipl.res
```

Repeat per effect. `scripts/build_windows.bat` does the whole loop for you; adjust the paths at
the top if your SDK is somewhere unusual.

> `pipltool.exe` writes a `.rc` whose resource id is 16000, matching the `resource 'PiPL' (16000)`
> line in the generated `.r`. If you rename anything, keep that number.

### macOS

The binaries are bundles, so the resource goes inside:

```bash
cd resources/pipl
for r in *.r; do
  plugin="../../build/plugins/MotionGraphicsToolkit_$(basename "$r" .r).plugin"
  Rez -o "$plugin/Contents/Resources/English.lproj/InfoPlist.strings" # (see below)
done
```

In practice Rez appends a resource fork to the *binary*, inside the bundle:

```bash
Rez -o /tmp/plugin.rsrc -append motiongraphicstoolkit_anamorphicglow.r
Rez -o /tmp/plugin.rsrc -append ../../build/plugins/MotionGraphicsToolkit_AnamorphicGlow.plugin/Contents/MacOS/MotionGraphicsToolkit_AnamorphicGlow
cp /tmp/plugin.rsrc ../../build/plugins/MotionGraphicsToolkit_AnamorphicGlow.plugin/Contents/MacOS/MotionGraphicsToolkit_AnamorphicGlow
```

The rules are:

* the binary must be a bundle with `Contents/MacOS/<binary>`,
* the PiPL has to be appended to that inner binary, not to the bundle directory,
* `xattr -c` the result if you copied it off a disk image, or Gatekeeper quarantine will block it.

`scripts/install.sh` does this as part of installing.

---

## 4. Install

| Platform | Directory |
|---|---|
| macOS | `/Library/Application Support/Adobe/Common/Plug-ins/7.0/MediaCore/` |
| Windows | `C:\Program Files\Adobe\Common\Plug-ins\7.0\MediaCore\` |
| Per-user (macOS) | `~/Library/Application Support/Adobe/Common/Plug-ins/7.0/MediaCore/` |
| Premiere Pro (Windows) | `C:\Program Files\Adobe\Common\Plug-ins\7.0\MediaCore\` |

```bash
# macOS / Linux
sudo ./scripts/install.sh

# Windows (elevated)
scripts\install.bat
```

The `7.0` in the path is not the After Effects version — it is the plug-in API generation, and it
has not changed in years. One install serves every CC version on the machine.

Then **restart After Effects**. Plug-ins are loaded at launch; there is no reload command.

The effects appear under **Effects & Presets → Motion Graphics Toolkit**.

## Troubleshooting

**The effect does not appear at all.**
The PiPL is missing or its out-flags do not match. Check the resource was attached (step 3), then
confirm the flags agree:

```bash
xxd -l 4096 build/plugins/MotionGraphicsToolkit_AnamorphicGlow.aex | grep -i pipl
```

The out-flags in the resource must be exactly what `src/ae/registry.cpp` sets. `make gen-pipl`
regenerates them and prints them, so the two can be compared directly.

**"the values in the pipl must correlate to the values set in the plug-ins global setup call"**
That is the mismatch above, reported explicitly. Regenerate with `make gen-pipl` and re-attach.

**Effects appear but render black, or crash on a 32-bit project.**
Check the plug-in was built against the same SDK you are running, and that `PF_OutFlag2_SUPPORTS_SMART_RENDER`
is set. It is for every effect here; if you have modified the registry, `make gen-pipl` and
re-check.

**The plug-in fails to load with no message at all.**
On macOS, quarantine:

```bash
xattr -cr "/Library/Application Support/Adobe/Common/Plug-ins/7.0/MediaCore/"
```

**A keyframe command from the Animation menu does nothing.**
Expected. The AEGP currently implements its menu and its About command only — see
[AEGP.md](AEGP.md) for what is left and why it was left.

## Building just the parts you can build anywhere

The core library, the keyframe tests and the After Effects *glue* tests all build without the
SDK, because the glue tests run against a stand-in host in `tests/ae_shim/`:

```bash
make test        # core + keyframes + glue
make test-glue   # only the glue suite
```

This is the development loop worth using. It catches type errors, parameter-id mismatches,
premultiply mistakes and protocol mistakes in a second, and leaves the SDK build for the things
only the SDK can tell you about.
